# A/B Test Project: Digital Wallet Checkout

> **Simulated data.** This is a personal portfolio project. All data is generated by code in this repo and does not come from a real company or product.

## Scenario

An e-commerce checkout currently requires buyers to type in card details (control). The treatment adds a one-tap digital wallet button. The question: **should we ship it?**

## What this project shows

- **Experiment design:** hypothesis, primary / secondary / guardrail metrics, power analysis, and test duration
- **Validity checks:** sample ratio mismatch and covariate balance, run before looking at results
- **Analysis:** two-proportion z-test with absolute and relative lift and a 95% confidence interval
- **Guardrails:** payment failure rate, so a conversion win can't hide a reliability problem
- **Segments:** exploratory cuts (device, new vs. returning) with a Bonferroni correction
- **Recommendation:** a ship / don't ship / run longer decision with reasoning

## Results (simulated)

| Metric | Control | Treatment | Result |
|---|---|---|---|
| Checkout conversion | 59.7% | 62.2% | +2.49 pts (95% CI +1.09 to +3.89), p = 0.0005 |
| Payment failure rate (guardrail) | 3.10% | 3.23% | No significant change (p = 0.63) |

**Decision:** ship. Sample size was set up front (about 9,300 users per group for 80% power to detect +2 pts). The data is generated with a built-in lift, so the value of this project is the method, not the finding.

## Run it

```bash
pip install numpy pandas scipy statsmodels matplotlib jupyter
jupyter notebook ab_test_wallet_checkout.ipynb
```

The random seed is fixed, so results are reproducible. Settings such as the baseline rate, minimum detectable effect, and true lift are at the top of the notebook.

## Try these

- Set `TRUE_LIFT = 0` to see an inconclusive result
- Set `TREATMENT_FAIL_RATE = 0.045` to see the guardrail block the launch even though conversion rises
- Change `MDE` and watch the required sample size change

## Limitations

- Simulated data with assumed effects, so it can't speak to real buyer behavior
- Segment results are exploratory and underpowered, because the test was sized for the overall effect
- A real test would also check for novelty effects, seasonality, and multiple metrics
